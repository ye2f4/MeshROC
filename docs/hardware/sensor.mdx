**MeshROC Sensor** 是基于 ESP32-C3 的低功耗传感终端，面向野外环境监测与长期数据采集场景。

## 核心规格

| 项目 | 规格 |
| --- | --- |
| 主控 | ESP32-C3（超低功耗） |
| 工作频段 | 470–490MHz |
| 网络角色 | `CLIENT_MUTE`（静默终端） |
| 供电 | 电池长期休眠 |
| 典型场景 | 环境监测、追踪、数据采集 |

:::caution 固件区分

Sensor 使用 **ESP32-C3** 主控，与其他三个型号的 ESP32-S3 **架构不同，固件不可混用**。烧录前请确认下载的是 C3 版本固件。

:::

## 设计定位

Sensor 与其他型号的根本区别在于：它不是给人用的，而是**长期无人值守运行的数据采集节点**。

因此设计的一切都围绕功耗展开——没有屏幕、没有键盘，绝大部分时间处于深度休眠，仅在采样与上报时短暂唤醒。

## 为什么选 ESP32-C3

相比 ESP32-S3，C3 在本场景下的优势：

- 单核 RISC-V 架构，静态功耗更低；
- 外设需求少，无需驱动屏幕与键盘；
- 成本更低，适合批量部署。

Sensor 不需要 S3 的算力与丰富外设，C3 是更合适的选择。

## 低功耗休眠防丢包

:::note MeshROC 关键修复

原版 Meshtastic 在深度休眠场景下存在**休眠期间丢包**与**发送过程被休眠中断**的问题。对于依赖长期休眠的传感节点，这类缺陷会直接导致数据丢失。

MeshROC 重写了电源管理逻辑，实现了休眠防丢包机制：确保发送流程完整结束后才进入休眠，并优化了唤醒时序以减少数据遗漏。

:::

这是 Sensor 型号必须使用 MeshROC 固件的核心原因。

## 部署建议

### 采样与上报周期

功耗与数据实时性直接矛盾，需要根据场景权衡：

- 上报越频繁，功耗越高，电池寿命越短；
- 对于环境监测类应用，通常数十分钟到数小时一次即可；
- 注意上报周期还会影响网络负载——大量传感节点同时上报会造成信道拥塞。

### 电池与低温

- 长期部署需重点考虑锂电池的**低温性能衰减**，冬季野外温度可能远低于电池正常工作范围；
- 建议按最差条件估算容量，并预留充足裕量。

### 网络覆盖

Sensor 是静默终端，不参与转发，因此**必须部署在骨干节点的覆盖范围内**。

部署前建议先用 [Walk](/docs/hardware/walk) 在目标位置实测信号质量，确认能稳定连接到骨干节点后再安装 Sensor。
