## 基础问题

### MeshROC 是什么？

MeshROC（Mesh Realm Of Connection，互联之域离线无线组网系统）是一套完全开源的 LoRa-Mesh 离线组网硬件与固件生态，兼容 Meshtastic 协议，针对中国山地与城市应急场景做了深度优化。

### 使用 MeshROC 需要考执照吗？

不需要。MeshROC 默认工作在 470–490MHz 免授权频段，属于微功率短距离设备的合法使用范围，与业余无线电（HAM）不同，无需操作证书。但仍需遵守发射功率与占空比等相关限制。

### 需要手机卡或者网络吗？

不需要。MeshROC 完全依靠 LoRa 无线电直接通信，不依赖任何运营商网络或互联网。手机只是作为显示与输入的客户端，通过蓝牙/WiFi/USB 连接设备。

### 通信距离能有多远？

这取决于地形、天线、发射功率与调制参数，差异极大：

- 城市密集建筑中，两台手持设备之间可能只有数百米到一两公里；
- 开阔地或准视距条件下，通常可达数公里；
- 山顶骨干节点之间在视距良好时，可实现数十公里的链路。

Mesh 的价值在于**多跳中继**：单跳距离有限，但通过骨干节点接力可以覆盖很大区域。

### MeshROC 和 Meshtastic 是什么关系？

MeshROC 基于 Meshtastic 协议构建，向下 100% 兼容，可与标准 Meshtastic 设备互通。同时 MeshROC 重写了路由、电源与射频子系统，并配套独立自研的国产硬件。详见[兼容性说明](/docs/compatibility)。

### 我可以把 MeshROC 设备和 Meshtastic 设备混用吗？

可以。只要调制参数与频道配置一致即可互通。需注意标准 Meshtastic 设备无法配置为静默终端，因此在混合网络中分层骨干的收益会有所降低。

## 选型与硬件

### 四个型号该怎么选？

| 需求 | 推荐型号 |
| --- | --- |
| 户外徒步、应急单兵通信 | MeshROC Walk（手持终端） |
| 山顶长期部署、扩大覆盖 | MeshROC Backbone（太阳能骨干） |
| 城市楼宇固定节点、接入内网 | MeshROC Gateway（POE 基站） |
| 野外环境监测、数据采集 | MeshROC Sensor（低功耗传感） |

大多数个人用户从 **MeshROC Walk** 开始即可。

### 可以不装天线就开机吗？

**绝对不可以。** 未连接天线时发射会导致射频功率无法正常辐射出去，可能永久损坏射频芯片。上电前请务必先接好天线。

### 电池能用多久？

取决于角色与配置。终端节点在分层骨干模式下不参与转发，功耗显著低于原版；Sensor 型号采用 ESP32-C3 并长期休眠，可实现数月级续航。骨干节点通常配太阳能或 POE 供电，设计为长期无人值守运行。

## 使用问题

### 为什么我的两台设备互相看不到？

按以下顺序排查：

1. **调制参数是否完全一致**（频段、预设档位）——这是最常见原因；
2. 频道名称与加密密钥是否一致；
3. 天线是否正确连接；
4. 距离是否超出单跳范围，中间有无遮挡；
5. 固件版本是否差异过大。

### 消息发出去了但对方没收到？

在 Mesh 网络中这通常意味着链路质量不足或信道拥塞。可尝试：

- 检查节点列表中对方的 SNR / RSSI 数值；
- 在两点之间增设骨干节点做中继；
- 若网络中转发节点过多，将终端配置为静默角色以降低拥塞。

### 网络里节点一多就开始丢消息？

这是洪泛机制的典型容量瓶颈。请启用[分层骨干路由](/docs/overview/mesh-alg)：把终端设备设为 `CLIENT_MUTE`，只保留少量选址良好的骨干节点参与转发。

### 大功率发射时屏幕闪烁或数据异常？

这是原版 Meshtastic 在自研 PCB 上的已知问题，源于射频干扰。MeshROC 固件内置了抗射频干扰处理（SPI 屏幕抗干扰驱动与 ADC 防抖滤波），请确认已刷入 MeshROC 固件而非原版固件。

## 开源与参与

### MeshROC 是开源的吗？

是。固件源自 GPL-3.0 的 Meshtastic，故固件沿用 **GPL-3.0** 开源；硬件以开源硬件形式在立创开源平台入库（星火计划）；文档与官网以 **MIT License** 开源。

### 我可以自己打板制作吗？

可以。PCB 工程文件与 3D 外壳模型均已开源，你可以自行打样制作。

### 如何参与项目？

欢迎参与固件开发、硬件迭代、文档完善与实地测试。详见[贡献指南](/docs/contributing)与[社区](/docs/community-docs)。
