## LoRa 物理层

LoRa（Long Range）是一种基于线性调频扩频（CSS，Chirp Spread Spectrum）的调制方式。相比传统的 FSK 调制，扩频带来的处理增益让接收机可以在**信号强度低于本底噪声**的情况下仍然正确解调，这是 LoRa 能实现远距离通信的根本原因。

关键参数包括：

| 参数 | 说明 | 对通信的影响 |
| --- | --- | --- |
| 扩频因子 SF | 7–12，每级翻倍符号时长 | SF 越大距离越远、速率越低 |
| 带宽 BW | 常用 125/250/500 kHz | 带宽越窄灵敏度越高、速率越低 |
| 编码率 CR | 4/5 – 4/8 前向纠错 | 冗余越高抗干扰越强、有效载荷越低 |
| 发射功率 | MeshROC Backbone 可达 30dBm | 影响链路预算与功耗 |

上述参数共同决定了「空中时间」（Time on Air）。空中时间越长，信道被占用越久，网络容量越低——这是 Mesh 网络设计中最核心的约束。

## Mesh 网络与消息转发

MeshROC 网络中没有中心节点。每个节点在收到一个此前未见过的数据包时，会根据策略决定是否转发。原版 Meshtastic 采用的是**受控洪泛**（managed flood）：所有节点都参与转发，通过跳数上限与去重表来收敛。

洪泛的优点是简单、无需维护路由表、拓扑变化时鲁棒；缺点是随着节点数量增加，重复转发会迅速消耗信道容量，形成**广播风暴**。

## 分层骨干路由（MeshROC 核心差异）

MeshROC 在洪泛的基础上引入了**分层骨干路由**机制，这是与原版 Meshtastic 最重要的架构差异。

网络中的节点被划分为两类角色：

- **骨干节点（Backbone / Gateway）**：部署在山顶、楼顶等制高点，承担绝大部分中继转发工作。
- **终端节点（Walk / Sensor）**：默认**静默**，只发送自己产生的消息，不参与他人消息的转发。

这样带来的效果是：

1. 参与转发的节点数量大幅下降，信道冲突显著减少；
2. 转发路径集中在链路质量最好的高点节点之间，多跳成功率更高；
3. 终端设备不再为转发他人消息而消耗电量，续航明显改善。

在此基础上，MeshROC 还实现了：

- **自适应跳数**：根据网络规模动态调整跳数上限，避免固定跳数在小网中浪费、在大网中不足。
- **信噪比择优**：在多条可用路径中优先选择 SNR 更高的链路，而非简单地「先到先转发」。

:::info

分层骨干是一种策略优化，**不改变协议帧格式**。因此启用了分层骨干的 MeshROC 网络，依然可以与标准 Meshtastic 设备正常互通。

:::

## 山地非视距（NLOS）优化

中国的应急通信场景大量发生在山区。山地环境的核心难点在于**非视距传播**：收发两端被山体阻挡，信号只能依靠绕射、反射与散射到达。

MeshROC 针对该场景的优化包括：

- 在链路预算紧张时自动切换到更高的扩频因子，以灵敏度换取速率；
- 动态功率调节：近距离通信自动降功率，减少对邻近节点的干扰；
- 增强的 LBT/CAD（Listen Before Talk / Channel Activity Detection）防碰撞机制。

## 设备角色小结

| 角色 | 典型型号 | 是否转发 | 供电方式 |
| --- | --- | --- | --- |
| 骨干节点 | MeshROC Backbone | 是 | 太阳能 + 锂电 |
| 城市基站 | MeshROC Gateway | 是 | POE 有线供电 |
| 手持终端 | MeshROC Walk | 否（默认） | 内置锂电 |
| 传感终端 | MeshROC Sensor | 否 | 电池长期休眠 |

关于各型号的详细硬件参数，请参阅[硬件文档](/docs/hardware-docs)。
