固件烧录完成后，需要完成初始配置才能正常通信。

## 连接设备

MeshROC 设备支持三种连接方式：

| 方式 | 适用场景 | 说明 |
| --- | --- | --- |
| 蓝牙 | 日常使用 | 手机 App 连接，最常用 |
| WiFi | 固定节点 | Gateway / Backbone 远程管理 |
| USB 串口 | 配置与调试 | 最稳定，适合首次配置 |

:::info

每台设备同一时间只支持**一个客户端连接**。若连接失败，请先断开其他已连接的客户端。

:::

首次配置建议使用 USB 串口方式，稳定且不受蓝牙配对问题干扰。

## 设置频段与调制参数

这是**最关键的一步**。同一网络中所有节点的调制参数必须完全一致，否则无法互相通信。

MeshROC 默认配置：

- **频段**：470–490MHz（国内免授权频段）
- **调制预设**：Long Fast（SF11 / 250kHz）

:::danger 合规提醒

请确认所使用的频率与发射功率符合当地法规。MeshROC Backbone 支持最高 30dBm 发射功率，在高功率部署前请务必确认合规性。

:::

若无特殊需求，**建议保持默认参数不变**。修改预设的权衡关系请参阅[无线电参数](/docs/overview/radio-settings)。

## 配置节点角色

这是 MeshROC 区别于原版 Meshtastic 的关键配置项。根据设备的部署位置选择角色：

```ini
# 骨干节点：参与消息转发
# 适用于 Backbone（山顶）与 Gateway（楼顶）
role = BACKBONE

# 终端节点：不转发他人消息，仅收发自身消息
# 适用于 Walk（手持）与 Sensor（传感）
role = CLIENT_MUTE
```

:::tip 为什么终端要设为静默

将手持与传感设备设为 `CLIENT_MUTE` 后，参与转发的节点数量大幅减少，可以显著降低信道拥塞、提升整网消息投递成功率，同时改善终端设备的续航。

这就是[分层骨干路由](/docs/overview/mesh-alg)的核心思想。

:::

## 设置节点名称

为设备设置一个易识别的名称，便于在节点列表中区分：

- **长名称**：完整显示名，如 `香山骨干节点`
- **短名称**：4 字符以内的缩写，用于屏幕等空间受限的场合

## 配置频道

频道决定了哪些设备能够互相通信。同一频道的设备需要保持：

- 相同的**频道名称**
- 相同的**加密密钥**

:::caution 安全提示

默认频道使用公开的默认密钥，**任何人都可以解密你的消息**。若需要保密通信，请创建自定义频道并设置独立密钥，然后通过安全渠道分享给你的团队成员。

:::

## 验证配置

完成配置后，用两台设备互相测试：

1. 确认两台设备的调制参数、频道与密钥完全一致；
2. 在节点列表中查看是否能发现对方；
3. 发送一条测试消息，确认能够送达；
4. 观察 SNR / RSSI 数值，评估链路质量。

若设备之间互相看不到，请参阅[常见问题](/docs/faq)中的排查步骤。
