MeshROC 设备基于 ESP32-S3 与 ESP32-C3 芯片。要通过 USB 烧录固件或使用命令行工具，电脑需要能正确识别设备的串口。

## 确认芯片使用的串口方案

不同板卡使用的 USB 接口方案不同，需要的驱动也不同：

| 方案 | 说明 | 是否需要额外驱动 |
| --- | --- | --- |
| 原生 USB-CDC | ESP32-S3 / C3 芯片内置 USB 外设直连 | 通常不需要 |
| CH340 / CH343 | 板载沁恒 USB 转串口芯片 | 需要 |
| CP2102 / CP2104 | 板载 Silicon Labs 芯片 | 需要 |

MeshROC 自研板卡多数采用 ESP32-S3 原生 USB，在 Windows 10/11、macOS 与主流 Linux 发行版上一般**免驱**即可识别。

## Windows

先将设备通过数据线连接电脑，然后打开**设备管理器**查看：

- 若在「端口（COM 和 LPT）」下看到 `COMx` 设备，说明已识别成功，无需安装驱动。
- 若在「其他设备」中看到带黄色感叹号的未知设备，则需要根据板载芯片安装对应驱动：
  - CH340 / CH343：安装沁恒官方 CH341SER 驱动
  - CP210x：安装 Silicon Labs 官方 CP210x VCP 驱动

安装完成后重新插拔设备。

## macOS

macOS 对 ESP32-S3 原生 USB 免驱。若使用 CH340 或 CP210x 芯片的板卡，需安装对应厂商的 macOS 驱动，并在「系统设置 → 隐私与安全性」中允许该内核扩展加载，然后重启。

识别成功后设备会出现为 `/dev/cu.usbserial-*` 或 `/dev/cu.usbmodem*`。

## Linux

主流发行版内核已内置 `ch341`、`cp210x` 与 `cdc_acm` 驱动，通常插上即可使用，设备表现为 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。

若出现权限不足（Permission denied），将当前用户加入 `dialout` 组：

```bash
sudo usermod -a -G dialout $USER
```

执行后需**重新登录**才能生效。

## 验证驱动安装

连接设备后，确认系统中出现了对应的串口设备：

```bash
# Linux
ls /dev/ttyUSB* /dev/ttyACM*

# macOS
ls /dev/cu.*
```

Windows 用户可在设备管理器的「端口（COM 和 LPT）」中查看分配到的 COM 号。

:::caution 排查提示

如果始终无法识别设备，请按以下顺序排查：

1. **更换数据线**——只能充电的线无法传输数据，这是最常见的原因；
2. 更换 USB 接口，优先使用主板直出接口而非扩展坞；
3. 部分板卡需按住 BOOT 键再插入 USB 才能进入下载模式。

:::

驱动就绪后，即可继续[烧录固件](/docs/getting-started/flashing-firmware)。
