分层骨干路由是 MeshROC 相对原版 Meshtastic 最重要的架构优化。本文说明如何在实际网络中部署。

## 角色划分

MeshROC 将节点分为两类：

```ini
# 骨干节点：承担消息转发
role = BACKBONE

# 终端节点：默认静默，不转发他人消息
role = CLIENT_MUTE
```

推荐的角色分配：

| 设备型号 | 推荐角色 | 原因 |
| --- | --- | --- |
| MeshROC Backbone | `BACKBONE` | 山顶制高点，供电充足 |
| MeshROC Gateway | `BACKBONE` | 楼顶固定部署，POE 供电 |
| MeshROC Walk | `CLIENT_MUTE` | 移动使用，需要节省电量 |
| MeshROC Sensor | `CLIENT_MUTE` | 长期休眠，功耗敏感 |

## 为什么终端要静默

在传统洪泛机制下，所有节点都参与转发。一条消息会在网络中产生接近节点总数的空口发射次数。由于 LoRa 空中时间较长且信道共享，节点数增加后信道很快饱和，消息投递成功率反而下降。

将终端设为静默后：

1. 参与转发的节点数从「全部」降至「少量骨干」，信道冲突大幅减少；
2. 转发集中在链路质量最好的高点之间，多跳成功率更高；
3. 终端不再为他人消息耗电，续航明显改善。

## 骨干选址原则

分层骨干的效果**高度依赖选址质量**。一个位置不佳的骨干节点不仅无益，还会占用信道。

推荐原则：

- **优先制高点**：山顶、楼顶、铁塔等视野开阔的位置；
- **保持准视距**：相邻骨干之间尽量无遮挡或仅有轻度遮挡；
- **避免过度堆叠**：同一区域部署过多骨干会退化回洪泛，失去优化意义；
- **稳定供电**：骨干需长期在线，应配备太阳能或 POE 供电；
- **天线优先**：天线的高度与质量对链路的影响，通常远大于发射功率。

:::tip

增加 3dB 发射功率只能带来有限的距离提升，而把天线抬高几米、换用增益更高的天线，效果往往显著得多。**优先投资天线与架设高度。**

:::

## 太阳能骨干节点

MeshROC Backbone 采用 CN3791 太阳能充电方案，可实现长期无人值守运行。

部署要点：

- **板功率留足裕量**：按冬季与连续阴雨天估算，建议按最低日照条件的 2–3 倍配置；
- **面板朝向**：朝南倾斜安装，倾角接近当地纬度；
- **电池选型**：注意低温性能，冬季山区温度可能远低于电池的工作下限；
- **智能电源策略**：MeshROC 固件会根据电量与光照动态调整占空比，在电量偏低时自动降低活跃度以维持基本可用性。

## 城市 POE 基站

MeshROC Gateway 使用 ESP32-S3 + W5500 有线网口，通过 POE 供电，适合楼宇固定部署：

- 单根网线同时解决供电与数据，布线简洁；
- 可接入内网，实现数据转发与远程管理；
- 7×24 小时稳定运行，适合作为城市网络的锚点。

## 长期运维

骨干节点部署后建议持续关注：

- **电量趋势**：太阳能节点在连续阴雨后是否能恢复；
- **链路质量**：相邻骨干之间的 SNR 是否稳定；
- **转发负载**：单个骨干是否承担了过多流量，是否需要增设分流。

## 混合组网提醒

:::caution

标准 Meshtastic 设备**无法**被配置为静默终端，它们始终参与洪泛转发。

如果你的网络中标准设备占比很高，分层骨干带来的容量收益会被明显稀释。详见[兼容性说明](/docs/compatibility)。

:::
