频道决定了哪些设备能够互相通信，以及消息如何加密。

## 频道的作用

两台设备要能通信，除了[调制参数](/docs/configuration/lora)一致外，还必须共享相同的频道配置：

- 相同的**频道名称**
- 相同的**加密密钥**

调制参数决定「能否在物理层收到信号」，频道则决定「能否解析出消息内容」。

## 主频道与次频道

MeshROC 支持配置多个频道：

| 类型 | 说明 |
| --- | --- |
| 主频道（Primary） | 默认收发频道，同时决定网络的基础参数 |
| 次频道（Secondary） | 附加频道，用于分组通信 |

主频道的名称参与密钥派生，因此**修改主频道名称会改变加密结果**，需要全网同步。

## 加密机制

MeshROC 沿用 Meshtastic 的加密体系，使用 AES 对消息载荷加密。密钥由频道配置生成，同一频道内的所有设备共享。

:::danger 默认频道并不安全

出厂默认频道使用**公开的默认密钥**。这意味着任何一台设备都能解密该频道上的消息。

如果你需要保密通信，**必须创建自定义频道并设置独立密钥**。

:::

## 创建自定义频道

1. 设置一个自定义的频道名称；
2. 生成随机密钥（推荐 256 位）；
3. 通过**安全渠道**将频道配置分享给团队成员。

MeshROC 支持通过二维码分享频道配置，这是最便捷的方式——但请注意：**二维码包含完整密钥，等同于明文口令**，不要在公开场合展示或截图分享到不受信任的渠道。

## 元数据不受保护

需要明确的是，加密只保护**消息内容**。以下信息在空口中是可见的：

- 发送方与接收方的节点 ID
- 数据包的大小与发送时间
- 跳数信息

这意味着即使内容无法解密，观察者仍可以推断出网络中有哪些节点、谁在与谁通信、通信活跃度如何。在对抗性环境中请充分考虑这一点。

## 实践建议

- **日常使用**：为你的团队创建独立频道并设置随机密钥；
- **公共中继**：若希望骨干节点为公众提供中继服务，可在默认频道上运行——转发不需要解密消息内容；
- **密钥轮换**：成员变动后应更换密钥，旧密钥持有者仍能解密历史流量。
